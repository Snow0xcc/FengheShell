# AI Copilot 面板 M1 真机回归手册（P1-N4）

## 1. 前言

- **适用范围**：`docs/AI_PANEL_REQUIREMENTS.md` §6.1 的 P1-N4，即 M1 面板在 Windows / macOS / Linux 上的真机回归。回归对象是包含本轮三项修复的桌面客户端，不替代单元测试或 CI。
- **代码基线**：`Cargo.toml` 中的 `0.7.8`；当前工作区起点为 `cadfb49dfdff9b9fd81e6f8c3d775ddba4302d43`。每次执行须记录实际构建版本 / 提交号，并确认构建包含：
  - **R1** 面板从 `ui/app.slint` 的 `for pane` 内容区移到 `quick-area` 下、与 `central` 平级；
  - **R2** `src/app/ai_callbacks.rs::tab_session()` 对内置/agent 会话回退 `resolve_builtin_session()`；
  - **R3** `crates/ai-copilot/src/triage.rs` 在 `run_command` 通道失败时写入 `outcome`，显示红色 `exit unknown`。
- **为什么手工执行**：CI 可以覆盖编译、单测和静态检查，但无法覆盖真实 IME 候选/输入法提交、Slint 窗口渲染与分屏几何、窗口管理器的拖 tab 行为，以及睡眠唤醒后的终端重绘。
- **执行前置**：完成 AI 服务连接测试；准备一个可丢弃的 SSH 测试会话；屏幕分辨率至少 1280×800；关闭会弹出通知的全屏应用；每项执行前保存终端工作。
- **结果标记**：`P` 通过、`F` 失败、`K` 已知限制、`N/A` 不适用。除明确标注 `K` 的 SSH Windows 远端项外，实际结果与预期不符即记 `F`。

## 2. 环境矩阵

每台平台至少一台真机；虚拟机/无头环境不能替代下表。版本号填写实际值，不用占位符提交回报。

| 平台 | 版本填写位置 | 中文 IME | htop / btop 全屏 | 2 pane 分屏 | 多窗口拖 tab | 睡眠唤醒 |
| --- | --- | --- | --- | --- | --- | --- |
| Windows 11 | 版本 / OS build，例如 `23H2 / 22631.xxxx` | 微软拼音；候选框、中英混输 | 各测一次 | 必测 | 必测 | 必测 |
| macOS | 系统版本 + build，例如 `14.x (23xxx)` | 简体拼音；候选框、中英混输 | 各测一次 | 必测 | 必测 | 必测 |
| Linux | 发行版 + 内核 + 桌面环境 | fcitx5 或其他实际 IME；候选框、中英混输 | 各测一次 | 必测 | 必测 | 必测 |

补充记录：屏幕分辨率与缩放比例、Slint 后端/显卡、SSH 远端 OS、PowerShell 版本（Windows 上必须为 **5.1**）、WSL 发行版、AI 协议/模型名称。

## 3. 分组 checklist

### A. 面板几何与 dock（重点验证 R1）

- [ ] A1 单 pane：关闭面板，记录终端右边界和列数；按 `Ctrl+Space` 打开面板。
  - 预期：终端可用宽度恰好减少面板宽度；面板贴右边界，右侧无空白条；面板不覆盖终端文字，终端内容自动重排且不被裁切。
- [ ] A2 单 pane：保持面板打开，在设置中将宽度从 360px 切到 520px，再切回 360px。
  - 预期：每次切换立即生效，无需重启或手动调整窗口；终端同步收缩/恢复，无残影、空白条或覆盖；两次最终宽度分别为 520px、360px。
- [ ] A3 将宽度设为 520px，完全退出应用后重新启动。
  - 预期：重开时面板仍为 520px，终端首次绘制即按该宽度布局，不出现先全宽后收缩的跳变。
- [ ] A4 再关闭面板，使终端恢复满宽；确认无残留遮挡。
  - 预期：终端占满原内容区；原面板区域无空白占位，不影响鼠标选中和点击终端。
- [ ] A5 创建 2 pane 分屏，每个 pane 各运行一个 shell，再打开面板。
  - 预期：整个窗口只渲染 **一个** AI 面板；两个 pane 都在面板左侧且各自可用；终端没有发生“面板宽度二次扣减”，没有面板覆盖任一 pane。
- [ ] A6 在 A5 的分屏状态下切换活动 pane、关闭其中一个 pane。
  - 预期：面板数量和位置不变；剩余 pane 立刻占满终端区；不出现每切一次 pane 就新增一个面板，也不出现空白区。
- [ ] A7 打开两个应用窗口，窗口 A 有分屏和面板，把 tab 拖到窗口 B，再反向拖回。
  - 预期：每个窗口最多一个面板；拖动后当前窗口不出现两个面板，原窗口面板不残留或被复制；tab 内容、终端尺寸和面板宽度均正常。
- [ ] A8 让 AI 生成一条耗时约 10 秒的只读命令并点击运行，在任务进行中连续关闭、打开面板两次。
  - 预期：会话不重置、不清空、不重新创建；执行结束前消息持续更新；重开后面板中可见完整提问、命令卡片和结果。

### B. Shell 上下文（重点验证 R2）

每项的提问都从**新建标签**开始，不经过 SSH 跳转；记录生成的命令卡片原文、实际 ShellKind（如界面可见）和退出状态。

- [ ] B1 Windows：打开内置 **PowerShell 5.1** 标签，提问“用一条命令列出当前目录中的文件”，点击运行。
  - 预期：命令基于 `Get-ChildItem` 等 PowerShell cmdlet；不出现 `uname`、`/etc/*` 或 POSIX `ls -la`；执行为 `executed · exit 0`。
- [ ] B2 Windows：打开内置 **CMD** 标签，提问“列出当前目录中的文件”，点击运行。
  - 预期：命令为 `dir` 或其他合法 CMD 命令；不出现 `uname` 或 `Get-ChildItem`；执行为 `executed · exit 0`。
- [ ] B3 Windows/Linux/macOS：打开内置 **WSL** 标签（Windows 必测），提问“打印内核名称并列出家目录”，点击运行。
  - 预期：命令使用 POSIX 形式（如 `uname -a`、`ls ~`），在 WSL 内执行且为 `executed · exit 0`；不出现 PowerShell cmdlet。
- [ ] B4 打开任一已安装的 **agent** 标签，提问“查看当前目录中的文件”，点击运行。
  - 预期：命令与 agent 实际本地运行环境一致：Windows agent 不出现 `uname`，POSIX agent 不出现 `Get-*`；执行成功且退出码与终端中直接执行一致。
- [ ] B5 新建到 **Linux 远端**的 SSH 标签，提问“打印内核名称”，点击运行。
  - 预期：生成 `uname` 等 POSIX 命令，在远端执行并返回 `executed · exit 0`；不使用本地 Windows cmdlet。
- [ ] B6 新建到 **Windows 远端**的 SSH 标签，提问“列出当前目录中的文件”，点击运行。
  - 预期：不崩溃、不丢会话；记录生成的命令、远端实际解释器、卡片状态和报错。若远端 shell 被误判或命令不兼容，标 `K` 并附证据；本项不按本地 PowerShell 标准判失败。

### C. 命令卡片红绿状态（重点验证 R3）

- [ ] C1 在当前标签让 AI 提议只读命令（PowerShell 用 `Get-Date`，POSIX 用 `date`），点击运行。
  - 预期：卡片显示绿色 `executed · exit 0`，输出区有命令结果，无失败标记。
- [ ] C2 明确要求 AI 提议 `sh -c 'exit 7'`（POSIX）或 `cmd /c exit 7`（Windows），点击运行。
  - 预期：卡片显示红色 `failed · exit 7`；输出中可见退出信息；不显示 `executed · exit 0`。
- [ ] C3 明确要求 AI 提议一条超过当前 `run_command` 超时的只读命令（如 `sleep 30`），点击运行并等待结束。
  - 预期：卡片显示红色 `timed out`；不会出现绿色成功态；超时后输入框和后续发送仍可用。
- [ ] C4 在 PowerShell 5.1 标签让 AI 提议并运行 `Get-Process`，观察等待全过程。
  - 预期：命令在超时阈值内返回，显示绿色 `executed · exit 0`；不误报 `timed out`。
- [ ] C5 使用可丢弃的 SSH 会话，在 AI 点击运行的瞬间断开会话 / 关闭远端通道，复现 `anchor_busy`、`session_channel_closed` 或 `anchor_lost`。
  - 预期：卡片显示红色 `exit unknown`，输出区含具体通道错误信息；不再出现绿色底、灰字 `rejected`。
- [ ] C6 让 AI 生成一条无害命令，点击拒绝 / Reject。
  - 预期：卡片保持灰色 `rejected`；终端中不出现该命令、无副作用；不显示 `exit 0`。
- [ ] C7 要求 AI 执行明显危险的命令（如 `rm -rf /` 或删除系统目录），不要点击运行。
  - 预期：shape validator 在提交前拦截，卡片状态为 `Pending`，显示红色 `blocked-reason` 及拦截原因；命令未进入终端、未被执行。

### D. 通用回归

- [ ] D1 在 AI 输入框用中文 IME 输入“请列出当前目录中的文件，并说明命令”，检查候选上屏后发送；再用 `Shift+Enter` 换行、中文/英文混输一次。
  - 预期：候选词不误触发发送；文本无丢字、乱码或重复；换行符合 `Shift+Enter`，发送符合 `Enter`；对话气泡完整显示输入内容。
- [ ] D2 在活动 pane 启动 `htop`，全屏后打开/关闭面板，再对 `btop` 重复一次。
  - 预期：TUI 只在面板打开时发生一次符合面板宽度的正常重排；面板不覆盖 TUI、不把终端二次压窄；无花屏、错位、重复边框或无法退出全屏。
- [ ] D3 面板打开、终端中有持续输出（如 `date` 循环）时让机器睡眠至少 10 分钟，唤醒解锁后等待 30 秒。
  - 预期：面板数量仍为一，宽度保持原档位；终端按当前窗口尺寸重绘且可继续输入；若会话断开，界面给出明确断线提示而不是显示仍在线的陈旧布局。
- [ ] D4 睡眠唤醒后重复 A1、B1 和 C1 各一次。
  - 预期：面板开关即时生效，PowerShell 命令卡片仍为 `Get-*` 且无 `uname`，只读命令返回绿色 `executed · exit 0`。

## 4. 如何回报

- 每行一个失败/限制项，字段固定：**平台与版本 / 构建号或 commit / 测试分组 ID / 标签类型与 pane 数 / 复现步骤 / 预期结果 / 实际结果 / `F` 或 `K`**。
- 截图必须带完整窗口和面板边界；几何问题附打开前、打开后、360px、520px、2-pane 各一张；卡片问题附完整卡片（含状态文案与输出区）；IME 问题附候选框和最终文本。
- 日志附应用日志中与 AI 请求、shell 上下文、`run_command`、通道错误相关的时间段，并写明机器时间与日志时间对应关系；请脱敏 API Key、用户名和路径。
- 汇总每个平台的 `P/F/K/N/A` 数量，并把结果贴到 P1-N4 跟踪项；只有所有 `F` 关闭且 `K` 经过确认后，P1-N4 才可标记完成。
